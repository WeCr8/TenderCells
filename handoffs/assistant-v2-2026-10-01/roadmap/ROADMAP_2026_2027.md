# TenderCells Assistant + Builder Roadmap

## Stage 1 — Public assistant readiness (Now)

**Outcome:** TenderCells is submission-ready for ChatGPT/OpenAI and Claude.

- B01 customer facade and Builder/Mission reads
- regression/safety tests
- reviewer farm
- TTL verification
- real screenshots
- demo video
- official logo assets
- signed MCPB
- store submissions

Exit gate:
`STORE_RELEASE_GATE.md` is fully checked.

## Stage 2 — Better assistant experience

**Outcome:** The public connector feels like TenderCells, not a raw tool list.

- B02 Mission / Builder / Device MCP App cards
- B03 Claude workflow skills
- B04 Animals / Habitats / Property Twin reads
- richer Farm Home
- use the real logo consistently in MCP metadata/cards/listings

Exit gate:
A new user can go:
`Farm → Alert → Mission → Builder → Device`
without learning MCP terminology.

## Stage 3 — Builder hardware credibility

**Outcome:** classroom/maker instructions can be trusted as build references.

- reference-check priority assets:
  - XIAO ESP32-S3
  - USB-C data cable
  - breadboard
  - LED / resistor
  - jumper families
  - JST / Dupont / WAGO / terminal block
  - Starter Node hardware
  - Chicken Tender Door BOM
- verify Chicken Tender Door book
- remove `concept` only after wiring/BOM/mechanical review
- M8 Replace the Button with a Sensor
- add sensor → MQTT → TenderCells OS bridge

Exit gate:
No authoritative hardware lesson depends on unverified generated art.

## Stage 4 — Education expansion

**Outcome:** TenderCells supports families, schools, 4-H/FFA and adult learners from the same content engine.

- M9 Invent a TenderCell
- printable manual export
- classroom/team mode
- teacher checkpoints
- parts kits/BOM views
- progress export without collecting unnecessary child data

## Stage 5 — Platform admin

**Outcome:** WeCr8 can operate content and connector health through a separate assistant surface.

- B05 admin read-only
- connector health
- asset review queue
- Builder validation state
- device/provisioning diagnostics
- B06 controlled content writes
- audit trail

Admin remains separate from customer `farm:read`.

## Stage 6 — Property/robot orchestration

**Outcome:** assistant can explain the real property system while physical safety remains hub/device-owned.

- affected-twin highlighting
- requested → acknowledged → confirmed state visualization
- live Roaming Roost occupancy/position
- irrigation/hive twins
- mobile/Safari QA
- robot capability manifest and schedule integration
- GPS/map/elevation work from existing roadmap

## Stage 7 — Stable generator and ecosystem

- mirror proven Builder into the Python generator
- contributor authoring workflows
- product-specific Builder books
- store analytics and usage-driven prioritization
- integration SDK/adapter documentation
